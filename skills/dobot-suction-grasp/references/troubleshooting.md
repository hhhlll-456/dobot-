# 故障排查：症状 → 根因 → 处理

**目录**

- A. ROS / 驱动 / 串口（A1–A6）
- B. 视觉 / 码检测（B1–B6）
- C. 运动 / 闭环（C1–C9）
- D. 标定错配（D1–D4）
- E. 停机条件

先做三件事，再看具体条目：

1. 看 `runs/<时间>/` 里对应阶段的 JSON（数值比图片快）；
2. 确认臂真的停在标准位（`/arm_b/state` 的 x/y/z 与 `b_standard` 一致）；
3. 确认吸盘状态（`/arm_b/suction` 返回的 `is_on` 只是指令回显，不是吸附力）。

**任何异常都先停，不要靠反复重试“撞”成功。**每次重试必须重新测量。

---

## A. ROS / 驱动 / 串口

### A1. `wait_state` 超时，或 `/arm_b/state` 没消息

**症状**：脚本启动后卡在等待状态；`ros2 topic echo` 一直空。

**根因（按概率排序）**：

1. 驱动进程攥着**已被删除的 tty**。换相机/插拔 USB 会让设备重新枚举，
   `ttyUSB0` 消失、臂变成 `ttyUSB1`，旧进程不报错但停发状态。
2. `arm_b_local.yaml` 里还写着固定的 `/dev/ttyUSB0`。
3. 起了两个驱动实例，抢同一个串口。
4. 臂没上电/急停被按下。

**处理**：

```bash
# 看驱动是否攥着已删除的设备
pgrep -af arm.launch.py
for p in $(pgrep -f arm_driver); do
  ls -l /proc/$p/fd 2>/dev/null | grep deleted
done

# 看 by-id 路径是否存在
ls -l /dev/serial/by-id/

# 只保留一个驱动实例；停掉旧的重启
```

`arm_b_local.yaml` 的 `port` 必须是：

```
/dev/serial/by-id/usb-Silicon_Labs_CP2102_USB_to_UART_Bridge_Controller_0001-if00-port0
```

不要写 `/dev/ttyUSBn`。

### A2. `ros2 topic echo /arm_b/state` 有发布者但收不到

**根因**：状态话题用 **best_effort** QoS，默认可靠订阅不兼容。

**处理**：

```bash
ros2 topic echo /arm_b/state --once --qos-reliability best_effort
```

### A3. 动作报 `0x22` / 机械臂卡住

**根因**：

- 悬停 z 太高（接近全伸奇异位形），再做水平 MOVL；
- 从低位斜线飞向目标，斜穿小车或超出关节范围；
- 低 y 平移时 J2 触限。

**处理**：

- `lift_mm` 保持 40，悬停 z 硬上限 70；
- 全程 L 形：先竖直抬 → 再水平 → 最后竖直降；
- 低 y（<40mm）用 `safe_goto`：先增大 x，再走 y；
- 清报警后重新回零：

```bash
ros2 service call /arm_b/clear_alarms std_srvs/srv/Trigger "{}"
ros2 service call /arm_b/home std_srvs/srv/Trigger "{}"
```

如果 `0x22` 反复出现，检查 `b_standard` 是否被误改、软限位是否被放宽。

### A4. 急停后所有目标 `REJECTED_ESTOP`

**处理**：先物理排除危险，再清急停和报警：

```bash
ros2 service call /arm_b/clear_alarms std_srvs/srv/Trigger "{}"
```

### A5. 吸盘服务返回 `ok=true`，但物体没吸住

**根因**：`ok` 只表示指令已下发；真机没有真空回读。可能是吸嘴没贴到
物体、物体表面漏气、吸盘管路脱落、抓取 z 偏高。

**处理**：不要相信服务返回。看抓取位确认的 `aligned` 与 `d_mm`，看
实际到位 z 与指令差，人工检查吸嘴/管路。把 z 降低几毫米重试。

### A6. 吸盘关不掉 / 物体放不下

**处理**：

```bash
ros2 service call /arm_b/suction fyp_interfaces/srv/Suction \
  "{on: false, wait_done: true}"
```

若 `is_on=false` 但物体仍被吸住，是真空残留：等 0.3–0.5s，或轻抬后
再释放。持续不掉说明电磁阀/管路问题，停机上人工处理。

## B. 视觉 / 码检测

### B1. 位姿来源是 `homography` 或 `cached`

**症状**：`--dry-run` 打印 `相机位姿来源 homography` 或 `cached`。

**根因**：

- `calib_file` 指向的会话里没有 `标定轮次/`；
- 原图文件名不是 `video<dev>_1600x1200.png`；
- `boards[round].seen_by` 没有当前相机 label；
- 原图里棋盘检测失败。

**处理**：修路径/文件名；必要时重拍该相机的棋盘轮次。`homography`
兜底精度较低，只能应急，不能长期用。

### B2. 码 22 看不到 / `require_suction` 报错

**根因**：臂姿态挡住码、码倾斜过大（`max_tilt_deg=45`）、反光、
码太小（30mm）或离画面边缘太近。

**处理**：

- 回标准位再测（标准位必须保证码 22 在视野中）；
- 降低环境光反射，避免正对灯；
- 检查 `suction.marker_mm=30.0` 是否与实际贴纸一致；
- 看 `runs/.../r*_base.jpg` 的标注，确认码框是否稳定。

### B3. 小车码 34 看不到

**症状**：标准位打印「⚠ 标准位没看到小车码 34：无法跟踪小车，退回世界坐标」。

**根因**：小车位置超出视野、码被物体/臂挡住、倾角过大。

**处理**：

- 调整小车停位，让码 34 与物体同时在标准位视野内；
- 退回世界坐标模式仍可抓，但臂推动小车后会跟丢，误差变大；
- 不要把 `cart_marker_id` 改成视野里没有的码。

### B4. 码高读数偏高 / 自动抓取 z 离谱

**症状**：码高比物理值高几十毫米；自动 z 算出负值（例如 −32.8mm）。

**根因**：倾斜小码的平面 pose 歧义。30mm 码在俯拍下有两个近似解，
倾角 8–18° 时高度可偏高约 50mm；倾角越大偏得越多。

**处理**：

- 优先把码贴平（倾角 <5°）；
- 用 5 帧中位，不要用单帧；
- 若仍偏，改用物理锚点 + `--grasp-z`（见 `calibration.md` 第 5.2 节）；
- 不要用「常数 z 修正」掩盖：先确认为什么偏，再决定是改码安装还是
  改标定。

### B5. 物体色块识别不到 / 识别错

**根因**：颜色不在候选范围、光照过曝/过暗、物体被臂挡住、背景有同色
物体、`min_area_px`/`min_fill` 过滤掉。

**处理**：

- 显式指定颜色：`--color green`；
- 看 `r*_base.jpg` 的色块标注；
- 抓取高度阶段机械臂会挡住物体，这是**预期**：此时不要依赖颜色，
  用码 22 相对码 34 的位置判断；
- 换物体时同步改 `size_mm`、`height_mm`，否则形状/反投影都会错。

### B6. 相机打不开 / 分辨率不对

**根因**：

- 设备号变了（插拔后 `/dev/videoN` 会漂）；
- 另一进程占着相机；
- 没有用 `CAP_V4L2 + MJPG`，拿到 640×480 或 YUYV；
- 四台 USB2 相机同时开流。

**处理**：

```bash
for d in /dev/video*; do
  echo -n "$d  "
  udevadm info -q property -n "$d" 2>/dev/null | grep -m1 '^ID_MODEL='
done
fuser -v /dev/video6
```

确认 `pnp_vision.grab_frame` 仍用 `CAP_V4L2`、`MJPG`、1600×1200。
需要多台时逐台采集，拍完立刻释放。

## C. 运动 / 闭环

### C1. `check_reach` 报超出可达范围

**根因**：物体太远/太偏；标准位没有把目标拉进臂的工作区；J 方向错了。

**处理**：

- 挪小车/物体，使目标落在 `reach_x_mm=[60,370]`、
  `reach_y_mm=[-310,310]`、`reach_radius_mm=300` 内；
- 检查 `--dry-run` 的 `Δ_arm` 方向是否合理（世界向量经 J⁻¹ 后应指向
  目标一侧）；
- 若方向整体反了，J 或世界系标定错了，重标。

### C2. 悬停闭环不收敛 / 来回振荡

**根因**：单帧码检测跳支；J 尺度不准；修正步长过大；目标跟着被推动的
小车跑。

**处理**：

- 已用多帧中位；若仍跳，查码倾角和 RMS；
- `max_hover_corrections=2`，不要无限加；
- 若臂一碰小车目标就跳，说明 `P_34` 在动，属正常跟踪；但闭环应在
  3mm 内停，不要追着噪声跑；
- 收敛不了就回标准位重拍，不要原地硬修。

### C3. 近抓取闭环残差仍 >2mm

**根因**：抓取高度处码 22 姿态变化、视野被物体/小车边缘切割、J 的
位姿相关误差。

**处理**：

- 这是最后一道闭环，残差 2–3mm 通常仍可吸（物体半宽 12.5mm）；
- 若 >6mm，先不要吸；回悬停位再走一次；
- 连续两轮都大，检查 `j_world` 与工具偏移是否同一世界系。

### C4. 抓取位确认 `aligned=false`（4–7mm）

**根因**：

- 单帧判据受码 34 平面姿态跳支影响（同一姿态 6°↔35°），单帧噪声 ±5mm；
- 容差设得过严（4mm 对 25mm 物体）；
- 工具偏移没跟上 J；
- 吸嘴真的不在物体上。

**处理**：

- 确认代码走的是 **5 帧中位**（`cart_relative_median`），看 `q_std`；
  帧间 std 应约 0.3mm；
- 容差按「物体半宽 − 吸盘半径」推导，25mm 物体用 7mm；
- 用 `tool_offset.py` 核对偏移；
- 若 `d_mm` 稳定在 10mm 以上，是真实偏差，不要放宽容差硬吸。

### C5. 确认通过、吸盘开了，但抬起来物体没跟着

**根因**：吸嘴只碰到物体边缘/顶面不平、z 还是高 1–3mm、吸盘管路漏气、
物体表面多孔/粗糙。

**处理**：

- 把 `z_retry_step_mm` 用上：第 2 次尝试会自动降 5mm；
- 检查实际到位 z 与指令差（脚本会打印），若差 >1mm 是臂没到位；
- 人工确认吸盘吸力；
- 换物体时降低 `grasp_clearance_mm` 或重新锚定 z。

### C6. 吸起后抬升途中掉落

**根因**：吸力不足、物体太重/表面漏气、抬升速度 8% 仍太快、管路弯折。

**处理**：降低抬升速度、检查吸盘直径与物体尺寸匹配、清洁吸盘。
不要用“吸住后猛抬”掩盖。

### C7. 重复抓取时位置越来越偏 / 小车被推走

**根因**：每次从标准位重新拍照时，小车已被前一次运动推动；世界坐标
模式跟不上。

**处理**：

- 确认标准位每轮都重新记录 `q_obj_cart`（脚本每轮开头会回标准位）；
- 保持码 34 可见；
- 用 `--no-home` 只在**已经回零且臂在标准位**时使用；它不是“跳过定位”，
  脚本仍会 `goto(base)`。

### C8. `--no-home` 后第一次动作异常

**根因**：臂实际不在标准位，或回零后零点漂移。

**处理**：去掉 `--no-home` 重跑；或先手动回零/示教标准位。

### C9. `--place-back` 放回位置不准

**根因**：放回用的是抓取时记录的 `last_target`，期间小车可能移动；
下降高度用的是 `last_gz`，物体已不在吸嘴上时接触高度不同。

**处理**：放回前确认小车没动；若小车会动，放回也应基于码 34 重新定位，
不要直接复用旧坐标。

## D. 标定错配（最隐蔽）

### D1. 换相机后所有坐标整体偏/旋转

**根因**：世界系随参考棋盘改变，但 `j_world` 还是旧的；或工具偏移还是
旧世界系的数值。

**处理**：

1. 用新会话重标 J（`--calibrate-j`）；
2. 用 `tool_offset_arm_mm` 和新 J 重表达工具偏移；
3. 重跑 `--dry-run`，确认目标方向与距离合理；
4. 再正式抓。

### D2. J 尺度正常但方向反了 / 轴对调

**根因**：世界系坐标轴定义变了（棋盘旋转 90°/镜像），或参考棋盘换了
一块。

**处理**：看 `j_meta.scale`、`axis_skew_deg`、`det`；重标 J。若新 J 的
列方向与旧 J 差 90°，说明世界系旋转了，这是正常的，**不要手工改 J**。

### D3. 工具偏移偏差随位置变化

**根因**：把「码心−吸嘴」当成了随位姿变化的误差，或世界系/臂坐标系
混用。

**处理**：工具偏移是刚体量，只随 J/世界系重表达；若它随目标位置变化，
说明还有别的误差源（J 不准、码倾斜、闭环不够），去查那些，不要加 trim。

### D4. 抓取 z 每次都需要不同的常数值

**根因**：误差随位姿变化，常数修正不成立。

**处理**：回到两级闭环 + 近抓取高度重算 z；检查 `grasp_trim_arm_mm`
必须为 `[0,0,0]`；不要用 `--grasp-z` 去补位姿误差（它只补整体高度偏置）。

## E. 停机条件

出现以下任一情况，立即停止，不要继续自动重试：

- 连续两轮抓取位确认失败；
- 任何碰撞、异响、物体被推飞；
- 报警无法清除；
- 状态话题中断；
- 相机位姿来源异常（`homography`/`cached`）且任务要求毫米级；
- 物体/小车已不在预期区域。

停机后报告：停在哪一步、`runs/` 路径、最后一次 `d_mm`/残差、报警码。
